# Стандарт оформления `agents/<agent-id>.md`

Этот файл описывает **как именно** оформлять per-agent правила. Соблюдение стандарта позволяет:

- Добавлять новых агентов единообразно
- Читать один файл в начале сессии и иметь полный контекст
- Сравнивать правила между агентами

## Расположение

```
master-vault/agents/<agent-id>.md
```

`<agent-id>` — kebab-case, без пробелов. Имя файла совпадает с `agent_id:` в frontmatter.

## Обязательный frontmatter

```yaml
---
agent_id: <agent-id>
display_name: <человеческое имя>
status: active | skeleton | deprecated
reads_on_start: [<список файлов читаемых при старте>]
tools: [<основные tools>]
context_limit: <approximate token budget>
---
```

`status`:
- `active` — агент используется, правила обкатаны
- `skeleton` — placeholder, контент минимальный с TODO
- `deprecated` — больше не используется, файл для истории

## Обязательные секции (6 штук, в порядке)

### 1. `## When to read`

Что подгружается в контекст при старте сессии. Минимум — сам файл `agents/<agent-id>.md`. Если есть общие правила в `agents/shared.md` или подобном — указать его тоже.

### 2. `## Token economy`

Что **НЕ** грузить целиком. Перечислить файлы / папки которые слишком большие или редко нужны полностью. Указать стратегии selective load (grep / glob по триггеру).

### 3. `## Where to write`

Куда складывать новые заметки разных типов. Можно делать таблицей. Опционально — пороги записи (когда вообще заносить).

### 4. `## Session save`

Что делать при завершении сессии. Чек-лист действий: создать session note → обновить state-файлы → (опционально) git commit → внешние интеграции.

### 5. `## Specifics`

Что уникально для этого агента:
- Tool inventory
- Hooks / skills / settings (где живут на OS уровне)
- Quirks и edge cases
- Что агент **НЕ** делает

### 6. `## Pre-flight checklist`

Что проверить перед vault-операцией. 5-8 пунктов чек-листа.

## Naming

- Файл = `<agent-id>.md`
- Frontmatter `agent_id:` совпадает с именем файла
- Никаких `(old)` / `(deprecated)` префиксов — используй `status:` в frontmatter

## Token budget per file

| Status | Рекомендуемый размер |
|---|---|
| `active` | 60-120 строк |
| `skeleton` | 20-40 строк (обязательные секции + TODO) |
| `deprecated` | как был |

Чем меньше — тем дешевле cold-start для агента. Если выходит больше 120 строк — подумай что вынести в общий файл (например `agents/shared.md`).

## Общие правила

Если хочешь общие правила для всех агентов — создай `agents/shared.md` и ссылайся на него из каждого `agents/<id>.md` через `[[shared]]`. Не дублируй контент — wiki-link работает.

## Как обновлять

- Изменение специфики агента → редактируй только `<agent-id>.md`
- Изменение общих правил → редактируй `agents/shared.md` (если он есть)
- Изменение стандарта оформления → редактируй этот файл
