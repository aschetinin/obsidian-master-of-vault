# Sync layer — синхронизация vault между устройствами

Единая память для агентов по определению живёт на нескольких машинах: рабочий компьютер, сервер где крутятся агенты, возможно второй комп или телефон. Без слоя синхронизации vault привязан к одной машине.

Этот слой **намеренно не зашит** в шаблон — выбор зависит от твоей инфраструктуры. Ниже варианты и одна важная грабля.

## Git ≠ синхронизация устройств

Vault под git закрывает **версионирование** (история изменений, откат, ветки). Но git — это **ручная** синхронизация: нужно `commit` на одной машине и `pull` на другой. Не realtime, требует дисциплины.

Для **живой** синхронизации файлов между устройствами нужен отдельный механизм. Git и file-sync решают разные задачи и хорошо работают вместе (см. граблю ниже).

## Варианты

| Вариант | Realtime | Цена | Приватность | Когда выбрать |
|---|---|---|---|---|
| **Только git** | Нет (ручной pull) | Бесплатно | Зависит от remote | Работаешь с одной машины; sync нужен редко |
| **Obsidian Sync** | Да | Платно (подписка) | Шифрование, серверы Obsidian | Не-технический, хочешь «просто работало», в т.ч. мобильный |
| **Syncthing** | Да | Бесплатно | Peer-to-peer, ничего в облаке | Технический; несколько своих машин; полный контроль |
| **Облако (iCloud / Dropbox / GDrive)** | Да | Бесплатно/платно | У провайдера | Уже пользуешься облаком; не против что файлы там |

Можно комбинировать: например git (версионирование) + Syncthing (живой sync файлов).

## Грабля: `.git/` и file-sync конфликтуют

Если синхронизируешь vault **файловым** sync'ом (Syncthing, iCloud, Dropbox) **и** ведёшь git на нескольких машинах одновременно — папку `.git/` нужно **исключить** из файловой синхронизации.

**Почему:** `.git/` содержит pack-файлы и индекс. Если их синхронизировать параллельно с `git commit` / `git pull` на разных машинах — возникают гонки, git-репозиторий повреждается.

**Как правильно:**
- `.git/` живёт **отдельно** на каждой машине (не синхронизируется)
- Файлы заметок (`.md`) синхронизирует file-sync в реальном времени
- git-историю подтягиваешь вручную `git pull` когда нужно версионирование

Это неочевидно и стоит дорого если наступить — поэтому вынесено отдельным разделом.

## Пример: исключения для Syncthing

Syncthing использует файл `.stignore` в корне синхронизируемой папки. Пример обезличенного содержимого:

```
.DS_Store
.git/
.obsidian/workspace*.json
.obsidian/cache
.obsidian/plugins/*/data.json.bak
.trash/
*.tmp
*.swp
.sync-conflict-*
```

Замечания:
- `.git/` — исключён (см. граблю выше)
- `.obsidian/workspace*.json` — локальное состояние UI каждой машины, синхронизировать не нужно
- `.sync-conflict-*` — файлы конфликтов Syncthing; исключаются из дальнейшего sync, но локальные копии остаются для ручного разбора

**Замечание по правилу R3** (корень vault — только `.gitignore`, `.master-vault-marker` + папки): если используешь Syncthing, `.stignore` обязан лежать в корне folder (Syncthing ищет его только там, перенести нельзя). Это документированное исключение — добавь его в свои правила.

## Рекомендации по топологии (если несколько машин)

- **Hub + peers:** одна всегда-онлайн машина (сервер) как hub, остальные (ноутбук, второй комп) — peers. Hub гарантирует что sync произойдёт даже если два устройства не онлайн одновременно.
- **Транспорт:** для своих машин — приватная сеть (VPN типа Tailscale/WireGuard) вместо публичных портов. Меньше поверхность атаки.
- **Конфликты:** периодически проверяй файлы конфликтов (`find <vault> -name '.sync-conflict-*'`) и разбирай вручную — какая версия победила.

## Мобильный (iOS / Android)

- **Obsidian Sync** — работает из коробки на мобильном
- **Syncthing** — на Android есть нативный клиент; на iOS нужен сторонний платный клиент (Syncthing не имеет официального iOS-приложения из-за ограничений фоновой работы)
- Альтернатива для мобильного как отдельный канал — obsidian-livesync (поверх CouchDB), но он синхронизирует между instance'ами Obsidian, **не** файловую систему — для агентов (которые читают файлы напрямую) не годится

## Итог

Sync layer — твой выбор под инфраструктуру. Минимум что нужно знать:
1. git ≠ realtime sync устройств — это разные задачи
2. при файловом sync **исключай `.git/`**
3. для своих машин — приватная сеть, hub + peers
